MVP Task Guide

Every job needed to build the MVP, in plain words. There are 119 jobs in 18 parts. Claude does most of them. This page shows what each job does and which ones are yours.

Step 1

How to read a job code

T-02.2
T = task (one job)
02 = part 2 of the project (part 2 is "Spikes")
2 = the 2nd job in that part

So T-02.2 means "part 2, job 2", and T-01.4 means "part 1, job 4". Each part below lists its jobs in order. You never need to remember codes: /next picks the right job for you.

Step 2

Who does what

Claude81

Claude builds these. You open a chat, type /next, read its short plan and say "go".

Checker15

A separate Claude checks a whole part with fresh eyes. Also run with /next. Nothing for you to do.

You23

Things only a person can do: give keys and documents, check answers, say yes to finished parts, run tests with real projects.

Your jobs now (days 1–2)

These decide whether the 3-week date holds. Claude is blocked on some jobs until you finish these.

  1. for T-02.1Get a Google Stitch API keySign in to Stitch and create an API key in its settings. Don't paste it into a chat or a file. The T-02.1 chat will show you how to save it safely in Windows.Why: lets Claude create screens in Stitch.
  2. for T-02.6Create a Langfuse project and get its 2 keysUse Langfuse cloud (my advice for v1: no server to run). Create a project and copy its public and secret key. Keep them out of chats and files too.Why: records every agent step so we can see what went wrong and how much usage it took.
  3. for T-02.5Find 3 real project briefs as PDFFrom past projects, with nothing confidential in them. Put them in one folder and tell the chat where it is.Why: real PDFs are messier than test documents; we must check quotes can be found in them.
  4. for T-02.3Figma: a Full seat on a paid plan, and one empty test fileShare the link to the test file with the chat.Why: tests whether Claude can draw screens straight into Figma.
  5. T-01.4Check the answer keys of the 12 test documentsIn eval/batch-1, batch-2 and batch-3, each document has an answer-key.md listing what a good result must find. Claude wrote them; fix anything wrong. Then add 2–4 real briefs.Why: every agent is scored against these. A wrong key gives a wrong score, and every agent build waits for this job.
  6. T-01.5Make the secret test setOpen a new Claude chat in a folder outside the project and paste the prompt from the T-01.5 task file. Claude writes 4 documents nobody building the agents will see.Why: the final test of each agent uses documents it has never seen, so we know it works on any project.
  7. T-01.3Invite the 2 other owners on GitHubThe repo is already on GitHub. Add your two teammates.Why: they can then run /next on their own computers and work goes faster.
  8. for T-18.2 · Friday week 1Pick 1–2 past projects for the first live testThe brief, plus what the team actually delivered for it.Why: we compare the system's output with real work done by people.

Your jobs later

Say yes to finished parts (the "Accept" jobs at the end of each part), a usability test with one non-technical person (T-09.5), approving the file formats (T-03.4), the Figma yes/no decision (T-15.2), live tests with your BA and a designer, and a pilot with 3–5 users in weeks 4–5.
