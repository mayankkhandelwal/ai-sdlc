## Answers

| # | Question | Answer | Proof |
|---|---|---|---|
| 1 | Does the PreToolUse hook see which agent is calling? | **Yes.** Calls made inside an agent carry `agent_type` (the agent's `name`) and `agent_id` (e.g. `a8440870192ea18b6`). Main-session calls have **neither field** | Run `identity`, table A |
| 2 | Can the hook see which agent is about to be started? | **Yes.** The tool that starts agents is named `Agent`; its input has `subagent_type` (`spike-a`) and `description`. So "no agent may use `Agent`" is a simple check on `agent_type` + `tool_name` | Run `identity` |
| 3 | Can the hook deny a call with a reason? | **Yes, both ways.** (a) exit 0 + JSON `hookSpecificOutput.permissionDecision: "deny"` with `permissionDecisionReason`; (b) exit 2 + reason on stderr. In both, the tool did not run and the model saw the reason word for word. A deny wins over `--allowedTools` | Runs `deny-json`, `deny-exit2` |
| 4 | Can the hook deny for one agent and allow for another? | **Yes.** Rule "deny `Read` when `agent_type == spike-a`": main read `a.txt`, `spike-b` read `b.txt`, `spike-a` was denied with the reason | Run `deny-agent` |
| 5 | If the hook crashes, is the call blocked? | **No, it goes through.** Python exception → exit 1 → treated as a non-blocking error; the files were read | Run `crash` |
| 6 | If the hook program is missing, is the call blocked? | **No.** `command not found` → exit 127 → call goes through. A missing *script* was blocked only by luck: Python exits **2** when it cannot open the file | Runs `nopython`, `missing` |
| 7 | If the hook runs past its timeout, is the call blocked? | **No.** Hook with `"timeout": 2` sleeping 30 s was killed and the call went through | Run `timeout` |
| 8 | Does the fix make it fail closed? | **Yes, all three.** Hook command `<command> \|\| exit 2` turns every non-zero exit (crash, missing program) into exit 2 = block. A timer inside the hook that exits 2 before the configured timeout (3 s timer, 10 s timeout) turns a hang into a block. Normal allow and JSON deny still work with the `\|\| exit 2` suffix | Runs `crash-fixed`, `nopython-fixed`, `timeout-fixed`, `allow-fixed` |

**ADR-19 confirmed, with a change in how it is built:** "all logic is wrapped so any error returns deny" is
**not enough** on its own. Wrapping inside the script can't catch a missing interpreter, a missing script, a
syntax error before the `try`, or a timeout. Fail closed needs three parts: (1) `try/except` → exit 2 in the
script; (2) `|| exit 2` on the hook command; (3) an in-script timer that exits 2 before Claude Code's timeout.

## Findings (general)

1. **The caller is known, by name.** `agent_type` is the `name` from the agent file, so the guard's allow lists
   can be keyed by agent name; "no `agent_type`" means the main session (the orchestrator).
2. **Exit codes other than 2 are "allow".** Claude Code treats exit 1, 127 and a killed (timed-out) hook as a
   non-blocking error and runs the tool. Any guard must force every failure to exit 2.
3. **Deny reasons reach the model word for word,** for both deny styles. Keep reasons short and free of secrets.
4. **The main session has more tools than expected.** It also called `ToolSearch`, `ListAgents` and
   `SendMessage` during the runs. The guard must deny any tool not on the caller's list (allow list, not deny list).
5. **The hold-out guard has the same gap.** `tools/guard_holdout.py` wraps its logic, but its hook command in
   `.claude/settings.json` has no `|| exit 2` and no timer; a missing Python or a hang lets the call through.
   Already in `plans/inbox.md`; now proven.
