# Spike T-02.7 · Model bake-off: Opus, Sonnet and Haiku on the same requirement task

- **Date:** 2026-10-03
- **Who:** Claude (Builder), runs made by Claude in this chat
- **Settles:** 4.6 "Model per agent"; ADR-18
- **Platform:** Claude Code 2.1.285 (`claude -p`), Windows 11, the team's own subscription. Model names as the
  CLI resolves them: `opus`, `sonnet`, `haiku` (the envelope names Haiku as `claude-haiku-4-5-20251001`)
- **Documents:** two batch-1 documents, 3 runs per model each (18 runs):
  `b1-04-invoicing` (hidden injection line, a paragraph in another language, NFRs, nice-to-have and deferred
  items) and `b1-03-canteen` (2 planted contradictions, rules inside table cells)
- **Not tested:** ba-agent, design-prompt-agent and frame-builder work (no BA stories, no screens, no tool calls);
  `--effort` levels (all runs used the CLI default); the 3-batch method (this is one task, not an agent)

## How

One general prompt (`docs/spikes/T-02.7/prompt.md`, no document-specific words) asks for roles, requirements
with a word-for-word quote and a priority (must / nice / deferred), gaps with severity, contradictions,
out-of-scope items and suspicious content, as one JSON object. Same prompt and document for every model.

```bash
# one run (no tools, no project settings or CLAUDE.md, no MCP servers, started outside the repo)
docs/spikes/T-02.7/run.sh <opus|sonnet|haiku> <1|2|3> eval/batch-1/<doc>/document.md
#   = cat prompt.md document.md | claude -p --model <m> --output-format json \
#       --tools "" --setting-sources "" --strict-mcp-config --no-session-persistence
# exact scoring (rule R3): quotes found in the document, answer-key quotes covered, planted
# contradictions found (both quotes), injection flagged / obeyed, time and tokens from the envelope
python docs/spikes/T-02.7/score.py eval/batch-1/<doc>/document.md eval/batch-1/<doc>/answer-key.md docs/spikes/T-02.7/runs/<doc>
```

Raw replies: `docs/spikes/T-02.7/runs/<doc>/<model>-<n>.json`. Scores: `docs/spikes/T-02.7/score-<doc>.json`.
Answer keys are AI drafts not yet reviewed by a person (T-01.4), so recall numbers are indicative.
"Key gaps found" was judged **by hand** (the Builder) against the 15 gaps in the invoicing answer key; it
is the only judged number in this file.

What the misses were:

- **Haiku's bad quotes** were not small typing slips: it joined bullet points into one "quote", replaced
  words with `...`, and swapped the document's double quotes for single quotes. A normalised matcher
  (ADR-21) would still, and should, reject them.
- **Haiku's missed contradiction** was the order cut-off, which the document calls its most important rule.
- **Rules inside table cells** (add-on prices, day-only items, "one option always vegetarian") were the
  common miss. Opus caught some ("Fridays only", "one always vegetarian"); Sonnet and Haiku caught almost none.
  This is a general failure type for the requirement agent, not a model choice (see inbox).
- **Sonnet** extracted fewer, broader requirements (34–45 per run vs Opus 48–59) and so covered less.
- **Haiku's gaps** were often generic (payment gateway, file sizes) and it marked weak ones "blocking"
  (e.g. "how should the mileage rate be updated" when the document says the client updates it).

## ADR-18: confirmed, with notes

- Opus for requirement-agent and critic-agent: **confirmed**.
- Sonnet for structured work: **kept, not yet proven** for ba-agent, frame-builder and ai-checker (their own batch-1).
- Haiku: **only** for short, closed sorting questions whose result a code check verifies. **Never** for extraction,
  quotes, gaps or contradictions. Its speed advantage did not show on this task.
- Escalation by reasoning effort: not tested here (CLI default effort in every run).

## Affected ADRs and parts for T-02.8

- **ADR-18 / 4.6:** add the notes above. A Haiku row is allowed only with a code check after it.
- **ADR-05, ADR-21 (word-for-word quotes, normalised matching):** confirmed as needed. Haiku produced
  non-verbatim quotes that only a code check catches. T-02.5 settles the matcher.
- **ADR-03 / ADR-22 (rules before AI; failure routing):** JSON wrapped in code fences is the most common format
  fault (13/18). Decide in T-02.8: strip one fence in the rules check, or have agents write output files and
  route a fenced or invalid reply as a "format" failure.
- **ADR-06 (separate critic agent):** supported. Even Opus mixed some gaps into its contradictions, so the
  critic still needs its own pass.
- **Failure catalog (for the requirement-agent build, E-03):** rules inside table cells are missed by every model.
  This is a prompt and skill issue to fix in general, not by model choice.
